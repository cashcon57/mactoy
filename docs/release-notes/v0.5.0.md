# Mactoy v0.5.0 — MBR installs and image folders in Manage Disk

Thanks to [@FrancYescO](https://github.com/FrancYescO) for [#11](https://github.com/cashcon57/mactoy/issues/11), and to [@swagdotsh](https://github.com/swagdotsh) for [#10](https://github.com/cashcon57/mactoy/pull/10) — Mactoy's first pull request from outside.

## Heads-up: new installs default to MBR

Install Ventoy used to always write a GPT partition table. It now defaults to **MBR**, the same as Ventoy2Disk, because MBR sticks boot on older BIOS PCs as well as modern UEFI machines. If you want the old layout, pick **GPT** on the Install tab before installing. Existing sticks aren't affected; Update Ventoy keeps whatever layout a stick already has.

## What's new

### MBR or GPT ([#11](https://github.com/cashcon57/mactoy/issues/11))

Install Ventoy has a new **Partition style** switch:

- **MBR** (default) boots on both legacy BIOS and UEFI. Choose it if you're not sure.
- **GPT** is the modern partition table. Choose it if a machine you'll use needs GPT.
- Drives larger than 2 TiB (about 2.2 TB) always use GPT, because MBR can't address them.

The confirmation sheet says which style will be written, and that choice is locked in when you confirm — Retry uses it too.

The MBR layout is the one Ventoy2Disk writes. After an MBR install, Mactoy reads the drive's first sector back and checks it against what was written, so a stick that wouldn't boot on older PCs can't report success.

### Image folders in Manage Disk ([#10](https://github.com/cashcon57/mactoy/pull/10))

Manage Disk used to list only images at the top of the drive. It now lists the same images Ventoy's boot menu will show:

- images in subfolders;
- only the folder set by `VTOY_DEFAULT_SEARCH_ROOT` in `/ventoy/ventoy.json`, if you've set one — and **Add ISO…** copies there;
- skipping folders that contain a `.ventoyignore` file, trash folders, anything deeper than `VTOY_MAX_SEARCH_LEVEL`, and the image types you've filtered out with `VTOY_FILE_FLT_*`.

Each row shows the image's path on the drive, since two folders can hold files with the same name.

### Smaller things

- **Update Ventoy on MBR sticks** moves the "active" flag back to the Ventoy partition if another tool moved it, as Ventoy's own updater does.
- **Running a second copy of Mactoy no longer gets stuck.** If the background helper belongs to another Mactoy version — say you opened this one from the DMG while another one is in Applications — Mactoy now switches the helper over to its own and tries again, instead of failing every time. If macOS asks you to approve the helper again, approve it and the install carries on.

## Install

```sh
# Download Mactoy-0.5.0.dmg from the release assets.
open Mactoy-0.5.0.dmg
# Drag Mactoy.app into /Applications, replacing the old version.
```

Apple-notarized. If macOS asks you to approve Mactoy's background helper again after updating, turn Mactoy on in System Settings → General → Login Items (called "Login Items & Extensions" on newer macOS).

## How this was tested

I can't test on physical USB sticks and old PCs, so this release was tested by running Mactoy's real install and update code against disk images, then booting those images in QEMU:

- MBR (Secure Boot support on and off) and GPT sticks boot to the Ventoy menu under both UEFI and legacy BIOS.
- Updating an MBR stick, including switching Secure Boot support and repairing a moved active flag, keeps it booting under both.
- GPT installs write the same bytes as v0.4.0: checked by installing with the released v0.4.0 and with this version and comparing the results.
- Manage Disk's list matches Ventoy's actual boot menu on the same stick, with and without a search root.
- 128 automated tests, and several rounds of independent code review.

## Known limitations

- **Tested in an emulator, not on physical machines.** QEMU's firmware follows the specs closely; some real machines don't. If an MBR stick from Mactoy won't boot where one from Ventoy2Disk does, please open an issue.
- **The active-flag repair** couldn't be shown to fix a real machine, because the emulated BIOS boots either way. It matches what Ventoy's own updater does.
- **Manage Disk can show a few images the menu won't:** `.efi` files (the menu shows them only when booted in UEFI mode), and anything hidden with the `image_list` / `image_blacklist` plugins, which Manage Disk doesn't read. When it can't tell what the menu will show — for example, per-boot-mode settings in `ventoy.json` — it lists the whole drive.
- **Manage Disk doesn't list files whose names start with `.`**, which Ventoy's menu does show. On a drive used from a Mac these are `._` metadata files, not images.
