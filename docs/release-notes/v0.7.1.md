# Mactoy v0.7.1: My Themes moves to Documents

Themes you keep in **My Themes** now live in a **Mactoy Themes** folder in your Documents, instead of inside Mactoy's Application Support folder.

## Why

Some themes in My Themes may be the only copy left: Mactoy saves a drive's theme there before replacing it or erasing the drive. Application Support is the kind of folder a full uninstall deletes (`brew uninstall --zap`, or an uninstaller app). In Documents, the themes are yours to keep, back up or delete, and removing Mactoy leaves them alone. Everything else Mactoy stores (caches and settings) stays in Library, where an uninstaller can remove it.

## What changes

- **Your themes move on their own.** The first time v0.7.1 starts, themes from v0.7.0 move to `~/Documents/Mactoy Themes`. Only whole themes are moved. Anything else in the old folder stays where it was, and the old folders are removed once they're empty. If a theme can't be moved (for example, macOS was told not to let Mactoy use Documents), the picker says so and shows the old folder.
- **The folder is only made when you need it**, the first time you save or import a theme. Until you've used themes, Mactoy doesn't look in Documents, so a new user isn't asked about Documents access on first launch. Until then, the picker's My Themes section has a **Show My Themes** button.
- **Find it from the app.** The picker's My Themes section says where the folder is and has **Show in Finder**. If macOS won't let Mactoy open the folder, the picker says so instead of showing an empty list.
- **Removing a theme moves it to the Trash**, since you may have changed files in it.
- Each theme is a folder named by its id (`custom-<name>-<8 characters>`), with a hidden file describing it. Renaming or moving a theme's folder hides it from Mactoy; moving it back brings it back.

## Fixed

- Saving a drive's theme that came from My Themes, when it's unchanged and still in My Themes, no longer adds a second copy.
- Before replacing a drive's theme or erasing the drive, Mactoy checks My Themes on disk and compares it with the drive's copy, so a theme deleted in Finder in the meantime, or changed on the drive, is still offered a save.

The helper didn't change, so updating doesn't ask you to approve it again.

## Install

1. Download `Mactoy-0.7.1.dmg` below and drag **Mactoy** to Applications, replacing the old copy.
2. Open it. If you had themes in My Themes, open the theme picker to check they're there.

## How this was tested

- **612 automated tests** (213 app, 399 library), including new ones for the move:
  - themes, their files, names and dates arrive intact;
  - anything that isn't a whole theme (a stray file, a folder with no description, a theme missing its files, a link) stays in the old folder, and so does that folder;
  - a theme already in the new folder isn't duplicated;
  - something else under a theme's name in the new folder is left alone, and the theme is reported as not moved;
  - when the new folder can't be written, every theme stays in the old folder, intact;
  - Mactoy's own half-saved leftovers are cleared, but never through a link;
  - with no themes to move, nothing is made in Documents;
  - after a relaunch, My Themes is only read once it's in use;
  - a theme deleted in Finder after My Themes was read, or changed on the drive, is still offered a save before a drive is changed or erased;
  - removing a theme and replacing a damaged one go through the Trash.
- **Two rounds of independent code review.**

**Not tested end to end:** the move on a real Mac running the app, including a Documents folder synced with iCloud Drive. Its logic is covered by the automated tests, which use temporary folders laid out like the old and new libraries.

If anything looks wrong, please open an issue.
