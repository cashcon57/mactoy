# v0.8.0: Safer writes

Milestone: [v0.8.0: Safer writes](https://github.com/cashcon57/mactoy/milestone/3). Second-to-last step on the [path to 1.0](../../README.md#roadmap): v0.8.0 makes writing a drive safer and checked, v0.9.0 adds what IT admins need, and 1.0 is a full run on real hardware.

## Why these together

Three of the five issues change the privileged helper (#21 cancel, #22 clear downloads, #26 the new verify step). macOS asks users to approve a changed helper, so they ship in one release and users approve once. The helper protocol goes from 0.5.0 to 0.8.0.

## In scope, in build order

### 1. Tests on every change (#18)

`themes.yml` already runs `swift test --no-parallel` on `macos-26`, but only when theme files change. Add `ci.yml`: the same test step on every pull request and every push to `main`, skipping changes that only touch Markdown or `docs/`. Cancel superseded runs on the same branch.

The QEMU boot harness (`scripts/e2e`) downloads Ventoy and boots two VMs, which is too slow for every PR. Run it weekly and on demand once it works on the runner; that is a follow-up inside #18, not a blocker for the rest.

### 2. Fewer leftover files (#22)

- Ventoy downloads (`VentoyDownloader`) and theme fetches use an ephemeral `URLSession`, so macOS no longer creates `~/Library/HTTPStorages/com.mactoy.Mactoy`.
- After a successful install or update, the helper deletes cached Ventoy versions other than the one it just used.
- New helper call `clearDownloads`, behind a **Clear Downloaded Files** menu item. It empties the helper's cache in `/Library/Application Support/Mactoy/Cache` and the app's cache in `~/Library/Caches/com.mactoy.Mactoy`.

### 3. The SECURITY.md gaps (#21)

- **exFAT format step:** call `reverifyFingerprintNow()` immediately before `newfs_exfat` (and before the `diskutil eraseVolume` fallback) in a fresh install. The last check today is before the partition write.
- **ASCII digits:** the BSD-name check in `InstallPlan` and the version check in `VentoyDownloader` accept any Unicode numeral through `isNumber`. Require ASCII digits.
- **`probeVentoy` input:** the helper validates the BSD name (`diskN`, whole disk, ASCII digits) before probing, with the same rule as `InstallPlan`.
- **Hardware ID:** add the USB serial number to `DiskTarget` when IORegistry has one, and compare it in `fingerprintMismatch` when both sides have it. Drives without a serial keep today's checks. Plans from an older app decode with the field missing.
- **Cancel:** new helper call `cancelCurrentRun`. The app shows **Cancel** while it's safe or useful:
  - Install and Update: during download and extraction only, before anything is written. Once writing starts, the button goes away; stopping halfway would leave a drive that doesn't boot and may not mount.
  - Flash image: also during writing, after a confirmation that the drive will be left unusable until it's erased or flashed again.

### 4. Streamed and verified image flashing (#20 and #26)

These change the same write loop in `RawImageDriver`, so they're one piece of work.

- **Streaming:** read the source in chunks and decompress as it goes. `.xz` uses Apple's `Compression` framework (`COMPRESSION_LZMA`, which reads the xz container); `.gz` uses the system zlib (`inflateInit2` with gzip headers). Memory stays at a few chunks whatever the image size. SWCompression stays for the theme importer.
- **Size:** for `.xz`, read the uncompressed size from the file's index before erasing, so a too-big image is refused up front and progress has a total. For `.gz` (whose stored size is only reliable under 4 GiB) and when the index can't be read, progress follows the compressed bytes read, and the write stops with an error before it would pass the end of the drive.
- **Unsupported files:** if Apple's decoder rejects an `.xz` file (for example an unusual filter), Mactoy says so before erasing the drive. Mactoy tests-decodes the first chunk before unmounting the drive, so a file it can't read never costs the user their drive.
- **Checksum before writing (#26):** an optional SHA-256 field on the Flash tab (paste it, or pick a `.sha256`/`SHA256SUMS` file). Mactoy hashes the file as picked and refuses to erase the drive if it doesn't match. Published checksums are almost always of the compressed download, which is what gets hashed.
- **Read-back after writing (#26):** while writing, hash the decompressed bytes; afterwards read the same length back from the drive and compare. A new `verifying` progress phase shows it. On by default, with a **Skip check after writing** option. A mismatch reports the flash as failed.

## Out of scope for v0.8.0

- Everything in the v0.9.0 milestone (MDM guide, CLI, offline use, lockable settings, activity log).
- Verifying Ventoy installs further; they're already checked after writing.
- Streaming formats other than `.xz` and `.gz`.

## How it's checked

- Unit tests for every item, including the decoders on truncated and corrupt input, and the size limit.
- `scripts/e2e`: flash a streamed `.xz` and `.gz` image to a disk image, verify it, and boot it in QEMU.
- Items 3 and 4 touch disk targeting and the write path, so each gets several independent review rounds before it's merged.

## Release

Not before Homebrew PR [#298276](https://github.com/Homebrew/homebrew-cask/pull/298276) is merged, so the cask under review doesn't go stale. After that, the cask update is a normal version bump.
